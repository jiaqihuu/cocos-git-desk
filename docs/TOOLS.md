Always available. `git_desk_*` tools talk to the Git service; `creator_*` tools call Creator asset-db, scene and preview messages directly.

## Runtime inspector and page event capture

Needs the embedded Debug Preview panel open in Creator. Uses only the Chrome DevTools Protocol of the embedded preview; no project code is required.

| Tool | Access | Parameters | Description |
| --- | --- | --- | --- |
| `runtime_inspector_hierarchy` | read | `contains?`, `activeOnly?:boolean`, `offset?:integer`, `limit?:integer` | Read the live Cocos node tree of the embedded debug preview (requires the Creator debug preview panel). |
| `runtime_inspector_layout` | read | `contains?`, `root?`, `activeOnly?:boolean`, `includeText?:boolean`, `maxDepth?:integer`, `limit?:integer` | Flattened UI layout of the running game for design comparison: every node with a UITransform as x, y, width, height in design pixels with a top-left origin, plus anchor, scale, opacity, font size, color, sprite frame and (opt-in) label text. |
| `runtime_inspector_layout_compare` | read | `design:array`, `tolerance?:number`, `scale?:number`, `offsetX?:number`, `offsetY?:number`, `root?`, `contains?`, `matchBy?`, `ignoreCase?:boolean` | Compare the running UI with design measurements: pass design boxes (name, x, y, width, height in the design canvas with a top-left origin, optional text, fontSize, color) taken from the design tool, and get per-element deltas against the live layout (dx, dy, dw, dh, text/fontSize/color matches), elements off tolerance, and what is unmatched on either side. |
| `runtime_inspector_inspect` | read | `uuid`, `sessionId`, `componentId?`, `all?:boolean` | Read one live node: transform, prefab source, referenced assets, owning view and components with their fields (same data as the Runtime Properties panel). |
| `runtime_inspector_select` | write | `uuid`, `sessionId` | Select a live node in the Creator runtime hierarchy/properties panels and bring them forward, so the person sees what the AI refers to. |
| `runtime_inspector_print` | write | `uuid`, `sessionId`, `componentId?` | Print a node or component to the Creator console as readable JSON and expose it as $gd0 in the preview DevTools; returns the same record. |
| `runtime_inspector_status` | read | — | Self-check of the debug tooling in one call: embedded preview binding, observer preference, collector hub (frame, session, node count, selection, pick/link switches), which Git Desk panels exist, what each open inspector surface currently renders (rows, names, selected node, component blocks, messages), and the extension's recent failures. |
| `browser_debug_export` | write | `screenshot?:boolean`, `compareDisk?:boolean` | Save one local evidence package under the debug output directory (agent-settings.json debug.outputDir, default ~/.cocos-git-desk/<projectId>/exports) with identity, UI states, merged timeline, pending requests and optional screenshot (default true). |
| `browser_debug_start` | write | `captureWebSocketPayloads?:boolean`, `includeExistingConsole?:boolean` | Start a fresh capture of the embedded preview page events (console, exceptions, network, navigation). |
| `browser_debug_status` | read | — | Show preview connection, capture target, buffer range, dropped-event count and the observer preference. |
| `browser_debug_events` | read | `sinceId?:integer`, `limit?:integer`, `latest?:boolean`, `categories?:array`, `levels?:array`, `query?` | Read a bounded page of captured events. |
| `browser_debug_summary` | read | `sinceId?:integer` | Summarize captured event categories, levels and recent errors since an event ID without dumping all logs. |
| `browser_debug_mark` | write | `label` | Add a short marker to the capture immediately before or after a manual reproduction step. |

## Project preview bridge

Needs the project to inject a preview bridge script that implements the bridge interface (`bridge.*` in `git-desk.config.json`). Tools are listed only when the bridge is enabled.

| Tool | Access | Parameters | Description |
| --- | --- | --- | --- |
| `browser_debug_enable` | write | — | Enable the project preview observer (page bridge) in the embedded debug preview when the task needs runtime evidence. |
| `browser_debug_disable` | write | — | Save the observer choice OFF for this machine/project and remove current observers from the page. |
| `browser_debug_connect` | read | — | Report the embedded preview connection, capture buffer and saved observer preference without changing anything. |
| `browser_debug_identity` | read | `compareDisk?:boolean` | Read preview identity, environment and loaded source stamp. |
| `browser_debug_hierarchy` | read | `contains?`, `activeOnly?:boolean`, `includeText?:boolean`, `maxDepth?:integer`, `limit?:integer` | Query bounded Cocos nodes with button/blocker states through the project bridge (needs browser_debug_enable). |
| `browser_debug_inspect_node` | read | `uuid`, `sessionId`, `includeText?:boolean` | Inspect a node through the project bridge using uuid and sessionId from a fresh browser_debug_hierarchy; stale sessions are rejected. |
| `browser_debug_state` | read | — | Read root UI layers and network connection/request counts without fetching server data or account information. |
| `browser_debug_timeline` | read | `afterSequence?:integer`, `limit?:integer` | Read client HTTP/unary RPC starts, completions, pending calls, pointer positions and exception locations recorded by the project bridge. |
| `browser_debug_ui_list` | read | — | List the UI views registered with the game (numeric view id uiid, name = last prefab path segment, prefab path, bundle, layer, whether currently open). |
| `browser_debug_ui_open` | write | `name?`, `uiid?:integer`, `args?:object` | Open a game view by name (last prefab path segment), full prefab path, or numeric view id (uiid), optionally with JSON args, through the project page bridge, as the game itself would. |
| `browser_debug_ui_close` | write | `name?`, `uiid?:integer` | Close a game view by name, prefab path or numeric view id (uiid), through the project page bridge. |
| `browser_debug_language` | write | `code?` | Without code: read the current language and the available list. |
| `browser_debug_mock_set` | write | `transport=rpc\|http`, `name`, `method?`, `response?:object`, `fail?:boolean`, `status?:integer`, `err?`, `once?:boolean`, `delayMs?:integer` | Register a preview-only fake response for one unary RPC method (transport rpc, name = full method such as pkg.v1.Service/Method) or one HTTP request path (transport http, name = path; optional method). |
| `browser_debug_mock_list` | read | — | List registered preview mocks with hit counts. |
| `browser_debug_mock_clear` | write | `transport?=rpc\|http`, `name?` | Remove mocks: transport + name removes one, transport alone removes all mocks of that transport, no arguments removes all; name without transport is rejected. |
| `browser_debug_stats` | read | — | Current-frame render statistics from the running game: fps, frame time, draw calls, instances, triangles and node count (what the engine profiler shows). |
| `browser_debug_capture_bodies` | write | `enabled:boolean` | Opt in to keeping RPC/HTTP request and response bodies in the preview timeline (browser_debug_timeline), redacted for secret-looking keys and bounded to 4 KB each. |

## Language key audit

Enabled only when `i18n.keyPattern` is configured in `git-desk.config.json`.

| Tool | Access | Parameters | Description |
| --- | --- | --- | --- |
| `creator_language_keys` | read | `keys?:array`, `since?`, `paths?:array`, `history?:boolean`, `csv?`, `limit?:integer` | Audit language keys touched by a change (keys match i18n.keyPattern in git-desk.config.json; the tool is listed only when it is set): which keys the uncommitted change (or the change since a revision) adds, where each is used, which fallback json files under i18n.directory have it (i18n.languages, or every json file there), placeholder consistency across languages, the commit that first introduced it, and a CSV draft for whoever maintains the remote copy, laid out by i18n.csvLayout (one row per key, or one row per key and language) with the i18n.csvColumns columns. |
